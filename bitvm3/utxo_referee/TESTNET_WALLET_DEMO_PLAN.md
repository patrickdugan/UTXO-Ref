# Testnet Wallet Demo Plan

This plan keeps the demo honest while still making it easy to show in a wallet
fork.

## Short Answer

You can point the wallet UI at Bitcoin testnet without storing the Bitcoin
testnet blockchain locally if the wallet uses a remote chain backend.

You cannot do local validation, wallet UTXO discovery, or transaction broadcast
with no chain source at all. For those actions, the wallet needs one of:

- a local Bitcoin Core testnet node
- a remote Bitcoin Core RPC node you control
- a remote Electrum/esplora-style backend
- imported proof artifacts generated by some other node

For the strongest live demo in this repo, use Litecoin testnet locally. The
chain abstraction already defaults to `litecoin-testnet`, and the M1 live
funding scripts understand the shared `BITVM_CHAIN` / `BITVM_RPC_*` environment.

## Recommended Demo Split

Use two modes in the wallet fork:

### Mode A: Bitcoin Testnet UI, Remote/Proof-Backed

Purpose: show the wallet story where reviewers expect BTC/LN language.

What it can show:

- LN-BTC input card
- TLUSD asset card
- liquidity patch stake
- Ark route assignment
- BitVM/UTXORef challenge evidence
- linked quote, allocation, stake, and challenge ids

What it should label clearly:

- Chain source: remote/proof-backed
- Taproot Asset mint/proof: prototype artifact unless `tapd` is wired
- Ark ASP: prototype artifact unless a real ASP backend is wired

Sidecar endpoints:

```text
GET  http://127.0.0.1:8787/v1/lnbtc-tlusd-liquidity-patch/wallet-view
POST http://127.0.0.1:8787/v1/lnbtc-tlusd-liquidity-patch/verify
POST http://127.0.0.1:8787/v1/lnbtc-tlusd-liquidity-patch/challenge
```

### Mode B: Litecoin Testnet Live Chain

Purpose: show a real UTXO chain harness with local RPC, wallet state, funding
artifacts, and replayable settlement evidence.

Environment:

```powershell
$env:BITVM_CHAIN="litecoin-testnet"
$env:BITVM_RPC_URL="http://127.0.0.1:19332"
$env:BITVM_RPC_USER="user"
$env:BITVM_RPC_PASS="pass"
$env:BITVM_WALLET="tl-wallet"
```

Probe and document what is reachable:

```powershell
node bitvm3/utxo_referee/lightning_live_testnet_demo.js
```

Run the M1 live chain replay:

```powershell
$env:LIVE_DEMO_RUN_M1="1"
$env:M1_PIPELINE_MODE="replay"
$env:M1_BROADCAST_FUNDING="0"
node bitvm3/utxo_referee/lightning_live_testnet_demo.js
```

For a fuller Litecoin wallet smoke test, follow `LTC_TESTNET_SETUP.md`:

1. start `litecoind -testnet`
2. provision role wallets and addresses
3. bootstrap the DLC draft from live wallet UTXOs
4. build funding PSBT and CET skeletons
5. select settlement paths
6. finalize funding with broadcast disabled for safe demos
7. generate the roll-forward handoff

## Wallet Fork UX

For a ZEUS or LDK demo wallet fork, add one experimental screen:

- `LN-BTC input`: shows the submarine-swap-shaped funding txid and UTXORef
  funding txid
- `TLUSD`: shows the BTC-based dollar asset amount and RFQ quote id
- `Stake`: shows staked TLUSD units, routing notional, lock, and target yield
- `Liquidity patch`: shows Ark route assignments and delivered liquidity
- `Enforcement`: shows the BitVM challenge id and slashable route violations

The UI should show a chain-source badge:

- `artifact`: deterministic local artifact only
- `remote`: remote chain backend
- `litecoin-testnet`: local Litecoin RPC
- `bitcoin-testnet`: local or remote Bitcoin testnet backend

The ZEUS mock integration files in this repo are:

- `integrations/zeus/tlusdLiquidityPatchClient.ts`
- `integrations/zeus/TlusdLiquidityPatchScreen.tsx`
- `integrations/zeus/WalletDemoSettingsScreen.tsx`
- `integrations/wallet-demo/walletBackendProfiles.js`

The sidecar reports the active wallet backend profile at:

```text
GET http://127.0.0.1:8787/v1/wallet-demo/config
```

It reports readiness, artifact freshness, chain target, and LND target at:

```text
GET http://127.0.0.1:8787/v1/wallet-demo/status
```

It serves a stress dashboard for tLTC/TLUSD fleet quantities at:

```text
GET http://127.0.0.1:8787/dashboard
GET http://127.0.0.1:8787/v1/wallet-demo/stress-dashboard
```

Use the local Litecoin backend during development:

```powershell
$env:WALLET_DEMO_PROFILE="litecoin-testnet-local"
node integrations/lightning-liquidity-lease-sidecar/server.js
```

Switch the same wallet UI to Bitcoin testnet LND for go-live testing:

```powershell
$env:WALLET_DEMO_PROFILE="bitcoin-testnet-lnd"
$env:BITVM_CHAIN="bitcoin-testnet"
$env:LND_REST_URL="https://127.0.0.1:8080"
$env:LND_GRPC_HOST="127.0.0.1:10009"
$env:LND_MACAROON_PATH="C:\path\to\admin.macaroon"
$env:LND_TLS_CERT_PATH="C:\path\to\tls.cert"
node integrations/lightning-liquidity-lease-sidecar/server.js
```

The key rule is that the wallet screen keeps calling the same TLUSD liquidity
patch endpoints. Only the backend profile changes from local Litecoin harness to
Bitcoin testnet LND.

## Honest Boundary

What is live today:

- deterministic end-to-end LN-BTC -> TLUSD -> stake -> Ark patch -> BitVM
  challenge evidence
- sidecar API and wallet-view responses
- Litecoin-oriented live chain harness and replay pipeline

What is still integration work:

- real `tapd` TLUSD issuance/proof import
- real Ark ASP VTXO membership and round signatures
- production BitVM challenge transaction construction
- Bitcoin testnet local validation unless a Bitcoin backend is configured
